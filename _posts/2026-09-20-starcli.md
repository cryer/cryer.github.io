### 导入

Agent CLI 这两年出了不少， Claude Code、Codex、Gemini CLI 等等，用了一圈之后还是想自己写一个：一来想完全按自己的习惯来，二来想要一个能随便接各种中转站的简单工具。于是用 TypeScript 写了 Star CLI。一开始只是想做个能调工具的简单 REPL，结果做着做着功能越加越多，现在也算是一个比较完整的小型 agent CLI 了。

项目地址：[github.com/cryer/star-cli](https://github.com/cryer/star-cli)，`npm install -g @cryer/star-cli` 就能装。

### 功能

日常用的那些都有：流式 REPL，斜杠命令带自动补全，`@file` 把文件内容注入上下文，`!cmd` 直接跑 shell。模型接入支持 OpenAI 兼容、Anthropic 和 OpenAI Responses 三种协议，baseURL 自选，所以各种中转站都能用，配 key 有 `/connect` 向导，不用手改配置文件。

工具方面，文件读写、glob、grep（这两个是自己实现的，零依赖）、bash（支持后台任务）、联网搜索抓取（DuckDuckGo，不用 API key）、todo 清单，还有 subagent 可以把聚焦的子任务丢给子代理去做，主对话保持干净。

权限分了五档：ask、auto、readonly、yolo、plan。危险命令、工作目录外的路径、`.env` 这类敏感文件是硬性规则，任何白名单都覆盖不了。写文件前会给彩色 diff 预览，按 `a` 可以永久放行同类操作。plan 模式下先做只读调研，计划批准之后才动手。写错了有 `/undo` 撤销上一轮改动，还有 `/rewind` 可以回滚到更早的检查点。

会话会自动持久化，断了能 `/resume` 恢复，还会自动给会话起标题。另外还有 `/fork` 分叉会话、`/search` 全局搜索、git 集成（`/commit` 起草提交信息、`/diff` 看改动）、长期记忆、自定义斜杠命令、钩子、token 成本估算这些，细节就不一一展开了，README 里写得很全。

### 架构

整体是普通的分层结构：入口、Ink 写的终端 UI、agent 主循环、工具和权限、底层的模型接入和会话持久化。层与层之间靠两个接口解耦：UI 面对的是 `ChatBackend` 接口，所以测试时可以拿一个假后端驱动整个界面；agent 主循环对外只吐 `StreamEvent` 事件流，REPL 把它渲染成卡片，print 模式把它序列化成 NDJSON，subagent 把它聚合成报告，同一条流水线三种消费方式。

还有两个设计上的原则。一是权限是两层防线：plan 模式下写工具干脆不发给模型，模型看不到，权限门再兜一层。二是一切皆可降级：LLM 摘要失败就退回纯截断，diff 预览失败就退回参数摘要，辅助功能永远不该阻塞主流程。

### 跑分

顺手在 Terminal-Bench 2.0 上随机抽了 20 个任务跑了一下，和 terminus-2 对比，用同一个模型：

| Agent | 模型 | 通过率 | 平均 token | 平均耗时 |
|---|---|---|---|---|
| Star CLI | Kimi K3 | 17/20 (85%) | 129.2K | 414s |
| terminus-2 | Kimi K3 | 9/20 (45%) | 49.5K | 484s |

token 花得多一些，通过率高出不少，算是拿 token 换成功率了。

### 结语

自己日常一直在用，有问题就顺手修。如果你也想要一个简单透明、随便接中转站的 agent CLI，可以试试看。
